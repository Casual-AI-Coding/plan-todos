# Release Notes 标准规范

本文档定义 Plan Todos 项目的 GitHub Release Notes 写作规范。

---

## 1. 格式结构

### 1.1 标题格式

```markdown
## 🎉 Plan Todos v{版本号}

## 🔧 Plan Todos v{版本号}

## 🚀 Plan Todos v{版本号}

## 🐛 Plan Todos v{版本号}

## 🔒 Plan Todos v{版本号}

## 🎨 Plan Todos v{版本号}
```

**Emoji 选择规则：**

| Emoji | 用途       | 场景                 |
| ----- | ---------- | -------------------- |
| 🎉    | 新功能发布 | 主要功能、重大特性   |
| 🔧    | 修复/重构  | Bug 修复、重构、改进 |
| 🚀    | 性能/优化  | 性能提升、优化相关   |
| 🐛    | Bug 修复   | 缺陷修复             |
| 🔒    | 安全修复   | 安全相关             |
| 🎨    | UI/主题    | 视觉、主题相关       |
| 🧪    | 测试       | 测试覆盖、测试新增   |

### 1.2 章节层级

```
## 🎉 Plan Todos v{版本号}

### 新增功能 / 重构 / 修复 / 性能优化

#### 子分类（可选，带 emoji）
- 具体变更项
- 具体变更项

#### 另一个子分类（可选，带 emoji）
- 具体变更项
```

---

## 2. 分类标准

### 2.1 主要分类

| 分类     | 标签           | 说明               |
| -------- | -------------- | ------------------ |
| 新增功能 | `### 新增功能` | 全新的功能特性     |
| 重构     | `### 重构`     | 代码重构、技术改进 |
| 修复     | `### 修复`     | Bug 修复、问题修正 |
| 性能优化 | `### 性能优化` | 性能提升相关       |
| UI/UX    | `### UI/UX`    | 界面、交互改进     |

### 2.2 子分类命名

使用中文 + Emoji 标识：

```markdown
#### 🖱️ 右键菜单

#### 🔔 通知系统

#### 📊 数据统计

#### 🔐 安全相关

#### ♿ 无障碍
```

### 2.3 变更项格式

**推荐格式（简洁）：**

```markdown
- 新增/修复/改进 xxx 功能
```

**详细格式（带说明）：**

```markdown
- **功能名称**: 详细描述
- **功能名称**: 详细描述
```

## 3. 安装方式表格（必须）

每个 Release 必须包含安装方式表格：

```markdown
---

### 安装方式

| 平台    | 文件                                         |
| ------- | -------------------------------------------- |
| Windows | `PlanTodos_{版本号}_x64-setup.exe` 或 `.msi` |
| macOS   | `PlanTodos_{版本号}_aarch64.dmg`             |
| Linux   | `.AppImage`, `.deb`, 或 `.rpm`               |
| Android | `.apk` 或 `.aab`                             |
```

**注意：**

- 分隔线 `---` 必须在表格前
- 平台按 Windows → macOS → Linux → Android 排序

## 4. 链接规范

### 4.1 CHANGELOG 链接

```markdown
**完整更新日志**: https://github.com/Casual-AI-Coding/plan-todos/compare/v{上一版本}...v{当前版本}
```

或

```markdown
详见 [CHANGELOG.md](https://github.com/Casual-AI-Coding/plan-todos/blob/main/CHANGELOG.md)
```

### 4.2 设计文档链接（可选）

```markdown
**设计文档**: `docs/plans/{日期}-{文档名}.md`
```

## 8. 版本号规范

遵循 Semantic Versioning：

| 版本类型 | 格式       | 说明         |
| -------- | ---------- | ------------ |
| 正式版   | `v0.8.1`   | 标准版本号   |
| Hotfix   | `v0.8.1-1` | 紧急修复版本 |

---

## 9. 写作风格

1. **语言**：中文撰写
2. **Emoji**：适度使用，每个子分类一个
3. **简洁**：每项变更一句话描述
4. **具体**：避免模糊描述，提供具体细节
5. **技术词汇**：使用官方技术名称（如 React Query、Tauri）

---

## 10. 发布检查清单

发布前确认：

- [ ] 标题包含正确版本号和 emoji
- [ ] 包含所有新增/重构/修复内容
- [ ] 安装方式表格格式正确
- [ ] 包含 CHANGELOG 链接
- [ ] 链接版本号正确
