## 优先级原则

1. **技术债务优先** - 先完成遗留的 TODO
2. **用户体验优先** - 体验优化 > 新功能
3. **性能保证** - 性能优化在数据量增长后进行
4. **渐进增强** - 先优化现有功能，再添加新功能

## 发布节奏

| 版本类型        | 周期   | 内容量           |
| --------------- | ------ | ---------------- |
| 小版本 (0.7.x)  | 1-2 周 | 1-2 个功能或修复 |
| 中版本 (0.8.0)  | 2-3 周 | 1 个主要功能     |
| 大版本 (0.9.0+) | 3-4 周 | 平台扩展级功能   |

## 风险与缓解

| 风险           | 缓解措施                           |
| -------------- | ---------------------------------- |
| 功能范围蔓延   | 严格控制每个版本的功能数量         |
| 技术债务积累   | 每个 sprint 预留 20% 时间处理债务  |
| 用户反馈不及时 | 每个版本发布后收集反馈再规划下一版 |
