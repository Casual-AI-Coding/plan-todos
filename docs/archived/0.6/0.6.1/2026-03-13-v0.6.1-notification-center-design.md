| 23#NV          |

### 1.4 约束与边界

- **桌面端优先**: 依赖 Tauri 后台运行，关闭窗口后仍可接收通知
- **通知插件依赖**: 必须配置至少一个通知渠道(飞书/钉钉/邮件/Webhook)才能发送提醒
- **数据兼容**: 需迁移旧 `reminder_minutes` 数据到 `reminder_times`
- **iOS 跳过**: 当前版本不支持 iOS 构建

### 1.2 用户痛点

1. **提醒分散**: Todo/Plan/Target 各自管理提醒，无统一视图
2. **单时间限制**: 仅支持一个提醒时间，无法设置多重提醒
3. **无历史追踪**: 不知道哪些提醒已发送，哪些待处理
4. **手动触发**: 需要用户主动查看，无自动推送

### 1.3 目标

1. 提供统一的通知中心，聚合所有到期提醒
2. 支持多提醒时间 (5分钟、1小时、1天前各提醒一次)
3. 记录通知历史，便于追踪
4. 自动定时检查并发送提醒

```sql
CREATE TABLE notification_history (
  id TEXT PRIMARY KEY,
  entity_type TEXT NOT NULL,        -- 'todo' | 'plan' | 'target'
  entity_id TEXT NOT NULL,
  title TEXT NOT NULL,              -- 实体标题
  message TEXT,                     -- 通知内容

  channel TEXT NOT NULL,            -- 'system' | 'feishu' | 'dingtalk' | ...
  status TEXT NOT NULL DEFAULT 'pending', -- 'pending' | 'sent' | 'failed'
  error_message TEXT,               -- 失败原因
  created_at TEXT NOT NULL DEFAULT (datetime('now'))

CREATE INDEX idx_notification_history_status ON notification_history(status);
```

### 5.3 useNotificationPolling Hook

````tsx
// src/lib/hooks/useNotificationPolling.ts

export function useNotificationPolling(interval = 30000) {
  const [dueReminders, setDueReminders] = useState<DueReminder[]>([]);
  const [pendingCount, setPendingCount] = useState(0);

  useEffect(() => {
    const poll = async () => {
      const reminders = await getDueReminders();
      setDueReminders(reminders);
      setPendingCount(reminders.length);

      // 如果有待发送提醒，自动触发通知
      if (reminders.length > 0) {
        await sendPendingNotifications(reminders);
      }
    };

    poll();
    const timer = setInterval(poll, interval);
    return () => clearInterval(timer);
  }, [interval]);

  return { dueReminders, pendingCount };
}
````

## 6. 定时提醒触发机制

### 6.1 触发流程

```
┌─────────────────────────────────────────────────────────────┐
│                     前端轮询 (每30秒)                        │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│               get_due_reminders() API                       │
│  查询: due_date IN (now, now + max_reminder_time)           │
│  匹配: reminder_times 包含接近当前时间的值                   │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│              返回 DueReminder[] (匹配的提醒)                 │
│  例: due_date=14:00, now=13:55                              │
│      reminder_times=[5, 60] → 匹配 5 分钟                   │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│              send_notification() API                        │
│  1. 获取已配置的通知渠道                                     │
│  2. 调用插件发送通知                                         │
│  3. 记录到 notification_history                             │
│  4. 更新 reminder_sent 状态                                  │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 后端匹配逻辑

````rust
// 检查提醒是否应该触发
fn should_trigger_reminder(
    due_date: DateTime<Utc>,
    reminder_times: &[i32],
    now: DateTime<Utc>,
    tolerance_minutes: i32,  // 容差，默认 1 分钟
) -> Vec<i32> {
    let minutes_until_due = (due_date - now).num_minutes() as i32;

    reminder_times.iter()
        .filter(|&&rt| {
            let expected = rt;
            let actual = minutes_until_due;
            (actual - expected).abs() <= tolerance_minutes
        })
        .copied()
        .collect()
}

### 6.3 后台通知机制

**架构选择**: 使用 Tauri 的系统托盘 + 后台轮询

```rust
// src-tauri/src/background/mod.rs

pub fn start_notification_checker(app: &AppHandle, interval_secs: u64) {
    let app_handle = app.clone();

    tauri::async_runtime::spawn(async move {
        let mut interval = tokio::time::interval(Duration::from_secs(interval_secs));

        loop {
            interval.tick().await;

            // 检查待发送通知
            if let Ok(pending) = get_pending_notifications_internal(&app_handle).await {
                for notification in pending {
                    if let Err(e) = send_notification_internal(&app_handle, notification).await {
                        error!("Failed to send notification: {}", e);
                    }
                }
            }
        }
    });
}
````

**说明**: 后台轮询在 Tauri 主进程中运行，即使前端窗口关闭也能正常发送通知。

### 6.4 实体删除时的清理策略

当 Todo/Plan/Target 被删除时，需要清理关联的通知数据：

```rust
pub async fn delete_entity_notifications(
    db: &Database,
    entity_type: &str,
    entity_id: &str,
) -> Result<(), String> {
    // 1. 删除 notification_settings
    sqlx::query("DELETE FROM notification_settings WHERE entity_type = ? AND entity_id = ?")
        .bind(entity_type).bind(entity_id)
        .execute(db.pool()).await?;

    // 2. 删除 pending 状态的 notification_history
    sqlx::query("DELETE FROM notification_history WHERE entity_type = ? AND entity_id = ? AND status = 'pending'")
        .bind(entity_type).bind(entity_id)
        .execute(db.pool()).await?;
    Ok(())
}
```
