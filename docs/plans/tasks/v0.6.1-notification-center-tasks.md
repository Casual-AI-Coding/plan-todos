### 1.8 后台通知轮询机制

**优先级**: P0 | **依赖**: 1.7

**文件**: `src-tauri/src/background/mod.rs` (新建)

**功能**:

```rust
use tauri::{AppHandle, Manager};
use std::time::Duration;
use tokio::time::interval;

pub fn start_notification_checker(app: &AppHandle, interval_secs: u64) {
    let app_handle = app.clone();
    
    tauri::async_runtime::spawn(async move {
        let mut timer = interval(Duration::from_secs(interval_secs));
        
        loop {
            timer.tick().await;
            
            // 检查待发送通知
            if let Ok(pending) = get_pending_notifications_internal(&app_handle).await {
                for notification in pending {
                    if let Err(e) = send_notification_internal(&app_handle, notification).await {
                        eprintln!("Failed to send notification: {}", e);
                    }
                }
            }
        }
    });
}
```

**在 main.rs 中启动**:

```rust
fn main() {
    tauri::Builder::default()
        .setup(|app| {
            start_notification_checker(app.handle(), 30); // 30秒轮询
            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

**验证**: 应用启动后后台轮询正常运行

```rust
use std::collections::HashSet;

fn deduplicate_reminders(reminders: Vec<DueReminder>) -> Vec<DueReminder> {
    let mut seen = HashSet::new();
    reminders.into_iter()
        .filter(|r| {
            let key = (r.entity_type.clone(), r.entity_id.clone(), r.minutes_until_due);
            seen.insert(key)
        })
        .collect()
}
```

### 1.10 实体删除时的通知清理

**优先级**: P1 | **依赖**: 1.3

**文件**: `src-tauri/src/commands/notifications.rs`

**新增函数**:

```rust
pub async fn delete_entity_notifications(
    db: &Database,
    entity_type: &str,
    entity_id: &str,
) -> Result<(), String> {
    // 1. 删除 notification_settings
    sqlx::query("DELETE FROM notification_settings WHERE entity_type = ? AND entity_id = ?")
        .bind(entity_type)
        .bind(entity_id)
        .execute(db.pool())
        .await
        .map_err(|e| e.to_string())?;

    // 2. 删除 pending 状态的 notification_history
    sqlx::query("DELETE FROM notification_history WHERE entity_type = ? AND entity_id = ? AND status = 'pending'")
        .bind(entity_type)
        .bind(entity_id)
        .execute(db.pool())
        .await
        .map_err(|e| e.to_string())?;

    Ok(())
}
```

**验证**: 删除实体后，相关通知数据被清理

### 2.3 useNotificationPolling Hook

**优先级**: P0 | **依赖**: 2.2

**文件**: `src/lib/hooks/useNotificationPolling.ts`

**功能**:
- 每30秒调用 `getDueReminders`
- 返回 `{ dueReminders, pendingCount, isLoading }`
- 支持手动刷新

**触发流程**:
1. Hook 每30秒调用 `getDueReminders` API
2. 后端匹配逻辑:
   - 查询所有 `notification_settings` 中 `reminder_times` 非空的实体
   - 计算每个提醒时间与当前时间的差值
   - 差值在容忍范围内(如±1分钟)则返回
3. 前端收到到期提醒后，调用 `sendNotification` 发送
4. 发送成功后调用 `markReminderSent` 标记已发送
5. 后端 `deduplicate_reminders` 确保不重复发送
